# Transcriber

Локальная транскрибация аудио на русском с разделением по говорящим. Всё считается на машине, ничего не уходит в облако.

- **Распознавание** — [GigaAM](https://github.com/salute-developers/GigaAM) (Sber, MIT). Версии `v3_e2e_*` дают текст с пунктуацией и нормализацией чисел.
- **Разделение говорящих** — `pyannote/speaker-diarization-community-1`. В самом GigaAM диаризации нет, только VAD, поэтому спикеры считаются отдельно и сшиваются с текстом по таймкодам слов.
- **Интерфейс** — FastAPI + страница в браузере: перетащил файл, дождался, скачал `.txt` или `.json`.

## Установка

```bash
brew install ffmpeg
python3 -m venv .venv
.venv/bin/pip install -e .
```

Затем токен Hugging Face — он нужен дважды: для VAD внутри GigaAM и для диаризации.

1. Заведите токен на [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens).
2. **Примите условия использования на страницах обеих моделей** — иначе скачивание вернёт 403:
   - [pyannote/segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0) — VAD внутри GigaAM
   - [pyannote/speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) — диаризация

   Именно `community-1`, а не `speaker-diarization-3.1`: в pyannote.audio 4.x старое имя обслуживается файлами новой модели, и ошибка доступа ссылается на репозиторий, условия которого вы не принимали.
3. Скопируйте `.env.example` в `.env` и впишите токен.

## Запуск

```bash
.venv/bin/uvicorn backend.app:app --port 8000
```

Откройте http://localhost:8000. Первый запуск скачает веса моделей (несколько ГБ) — это происходит один раз.

## Проверка и настройка

Смоук-тест модели без веб-сервера (заодно покажет, приходят ли таймкоды слов и пунктуация):

```bash
.venv/bin/python scripts/smoke_test.py
```

Подбор устройства и модели по факту, а не по ожиданиям:

```bash
.venv/bin/python scripts/benchmark.py запись.m4a
```

Обработка одного файла из терминала, без браузера:

```bash
.venv/bin/python -m backend.pipeline --input запись.m4a
```

## Настройки

Всё через `.env` (образец — `.env.example`):

| Переменная | Смысл |
| --- | --- |
| `GIGAAM_MODEL` | `v3_e2e_rnnt` точнее, `v3_e2e_ctc` быстрее. Только `v3_e2e_*` дают пунктуацию. |
| `ASR_DEVICE` | `mps` по умолчанию, на CPU в ~10 раз медленнее. Без MPS откатывается на `cpu` сам. |
| `DIARIZE_DEVICE` | `mps` по умолчанию, на CPU в ~7 раз медленнее. |
| `DIARIZATION_ENABLED` | Режим по умолчанию. Сам режим выбирается для каждой загрузки переключателем в интерфейсе; разделение по говорящим — около трёх четвертей времени обработки. |
| `SPEAKER_SNAP_WINDOW` | Насколько далеко (сек) слово может отстоять от интервала спикера, чтобы всё же быть ему приписанным. |
| `UTTERANCE_GAP` | Пауза (сек), по которой реплика одного говорящего разрывается на две. |

## Что стоит знать про производительность

Замеры на MacBook Air M4 (10 ядер, 16 ГБ), встреча 13.7 минуты, два говорящих:

| Стадия | cpu | mps (дефолт) |
| --- | --- | --- |
| диаризация | 512 с | 75 с |
| распознавание `v3_e2e_rnnt` | 247 с | 25 с |
| распознавание `v3_e2e_ctc` | 239 с | 22 с |
| весь пайплайн | 831 с | 101 с |

Выводы:

- **Результат на MPS побайтно тот же, что на CPU** — и разметка говорящих, и текст с таймкодами слов. Сверить на своей машине: `scripts/benchmark.py` печатает md5 текста для каждой связки.
- `transcribe_longform` из GigaAM на GPU включает fp16, и текст начинает расходиться с CPU. Поэтому приложение считает энкодер на MPS в fp32 своим циклом, а декодер оставляет на CPU.
- Задачи обрабатываются **строго по одной**. Модели занимают около 2 ГБ, а Air безвентиляторный — параллельная обработка приводит к троттлингу быстрее, чем к выигрышу.
- На длинных записях (час и больше) скорость может падать из-за нагрева — это нормально для Air.

## Структура

```
backend/
  config.py            настройки из .env
  app.py               HTTP API + отдача frontend/
  db.py                SQLite: задачи переживают перезапуск сервера
  worker.py            последовательная фоновая очередь
  pipeline/
    audio.py           ffmpeg -> 16 kHz mono wav
    asr.py             GigaAM: ленивый синглтон, энкодер на MPS в fp32
    diarize.py         pyannote, ленивый синглтон
    merge.py           слова + говорящие -> реплики
    render.py          .txt и .json
frontend/              одна страница, без сборки
scripts/               смоук-тест и бенчмарк
data/                  загрузки, wav, результаты, app.db
```
